# V2 — 기능·성능 확장 + 배포 준비 계획 (2026-11-25, Review-Tier: T1)

목표: Rust 판 Xdownload2 1.0.0(원본과 같은 기능)을 기능·성능이 훨씬 나은 2.0.0 으로 올리고, 포털 exe 직접 배포 기준 준비율 95% 를 만든다.

## 구조 사실 (실측)
- 1.0.0: `src/main.rs`(화면 + 작업 스레드 1개가 배치를 차례로 처리), `downloader/converter/binaries/proc/settings/i18n`, `ui/{theme,widgets,icons}`. 테스트 35 + 수동 1.
- 캐시된 yt-dlp 로 확인: `--no-quiet --print "after_move:XDL_FILE:%(filepath)s"` 가 최종 파일 경로를 한 줄로 낸다.
  `--embed-thumbnail --embed-metadata --embed-subs --write-auto-subs --sub-langs ko,en` 동작(exit 0). `--write-subs` 를 함께 주면 .vtt 가 남으므로 주지 않는다.
- 이 PC(RTX 5070 Laptop + AMD 내장): ffmpeg `h264_nvenc` exit 0, `h264_amf` exit 0, `h264_qsv` 실패.
- 1.0.0 의 mp4 format 은 avc1 을 먼저 고르므로 "최고 화질"도 1080p 에서 멈춘다(4K 는 avc1 이 없음).

## 운영자 확정
기능: 다운로드 큐 + 항목별 진행 / 포맷·화질 확장 / 편의 기능 / 변환 옵션 확장.
성능: 동시 다운로드 / GPU 변환 / 이미지 동시 변환 / 시작·준비 시간 단축.
배포: 포털에서 exe 직접 받기, 코드 서명 인증서 없음(서명 스크립트 자리만).
이미지 변환은 CPU 다중 코어(운영자 질문에 답함: 정지 이미지는 GPU 이득 없음).

## 설계

### 큐 (`src/queue.rs`, 화면과 분리)
- `Item { id, work, title, state, progress, speed, eta, note, file, job }`, `Work::Download{url, opts} | Work::Convert{source, opts}`.
- `State`: Waiting / Running / Done / Failed / Cancelled.
- 스케줄러(UI 스레드, 매 프레임): 종류별 동시 실행 한도 안에서 Waiting 을 시작한다. 한도 = 다운로드 `settings.parallel`(1..5, 기본 3), 동영상 변환 CPU 1 / GPU 2, 이미지 변환 = 코어 수(최대 8).
- 항목마다 스레드 1개 + `proc::Job` 1개. 결과는 `Msg{id, Update}` 채널 + repaint 요청. 옵션은 큐에 넣을 때 고정.
- 항목별 취소·재시도·삭제, 전체 취소, 끝난 항목 지우기. 작업 중에도 추가 가능. 창 닫기 = 전체 취소.
- 바이너리 준비는 전역 Mutex 로 한 번에 하나만(뒤 스레드는 기다렸다가 캐시를 쓴다). 실패 후 `yt-dlp -U` 는 세션당 1회만 실행하고 모두 그 결과로 재시도한다.

### 다운로드 옵션
- 포맷 MP4 / MP3 / M4A(재인코딩 없이 원본 오디오). 화질 최고 / 2160 / 1440 / 1080 / 720 / 480.
- 1080p 초과 요청은 먼저 `bv[height>1080][height<=N]` 을 고르고 없으면 기존 avc1 우선 체인(호환성)으로 내려간다.
- 자막 넣기(ko,en, 자동 자막 포함, MP4 만), 썸네일·정보 넣기, 플레이리스트 전체/한 개만(`--yes-playlist`/`--no-playlist`).
- 진행 줄에서 %·속도·남은 시간, `Downloading item X of Y`, 최종 파일 경로(`XDL_FILE:`)를 읽는다.

### 변환 옵션
- 동영상 → MP4(H.264; 높이 원본/1080p/720p; 화질 우선·균형·용량 우선) / MP3 / GIF. 이미지 → JPG / PNG / WebP. 하위 폴더 포함 선택.
- GPU: ffmpeg 로 1프레임 시험 인코딩해 `h264_nvenc → h264_qsv → h264_amf` 중 되는 것을 한 번 고른다(설정에서 끌 수 있음). GPU 인코딩이 실패하면 그 항목은 libx264 로 다시 한다.
- 산출물 이름: MP4→MP4 는 `_h264_<1080p|720p|src>` 접미사, 그 밖은 확장자만 바꿈, 겹치면 `-2..`. 폴더 탐색은 산출물 접미사 파일을 건너뛴다. 대상 형식과 같은 확장자의 이미지는 건너뛴다.

### 편의
- 창이 포커스를 받을 때 클립보드에 새 유튜브 링크가 있으면 링크 칸에 추가(설정, 기본 켬). 크레이트 `arboard`(이미 eframe 이 쓰는 것).
- 파일·폴더를 창에 끌어다 놓으면 종류에 맞게 변환 큐에 넣는다. 실행 인자로 링크·파일을 받는다.
- 모두 끝나면 저장 폴더 열기(설정, 기본 끔).
- 히스토리: 제목·파일 경로 기록(구버전 항목 호환), 두 번 클릭 = 파일 열기(없으면 폴더), 폴더 열기 / 다시 받기 / 삭제.

### 시작·준비
- 시작 직후 백그라운드: yt-dlp·ffmpeg 준비 → 하루 1회 `yt-dlp -U` → GPU 인코더 확인 → 앱 새 버전 확인. 상태는 아래 줄에 표시, 실패해도 조용히 넘어가고 필요할 때 다시 시도.

### 화면
- 제목줄 탭: 다운로드 / 변환 / 기록 / 설정. 다운로드·변환 탭 아래에 공용 큐 목록. 창 기본 620×820.
- 직접 그린 위젯에 접근성 정보(`widget_info`)를 넣는다(화면 읽기 + UI 자동화 검증).

### 배포 준비 (포털 exe 직접 배포)
1. exe 메타데이터(제품명·설명·버전·저작권) + 매니페스트(longPathAware, supportedOS, DPI).
2. 정적 CRT(`+crt-static`) — VC++ 재배포 패키지 없이 실행. release: strip, codegen-units 1.
3. `packaging/release.ps1`: 테스트 → release 빌드 → `dist/`에 exe, SHA256, `xdownload2.json`(버전·주소·해시) 생성, 인증서가 있으면 서명.
4. 앱 새 버전 확인: `https://xtool.duckdns.org/dl/xdownload2.json` 을 읽어 더 높으면 제목줄에 알림(누르면 받기 주소를 브라우저로). 파일이 없으면 조용히 넘어간다.
5. 문서: `CHANGELOG.md`, `docs/USER_GUIDE_KO.md`(SmartScreen 안내, 데이터 위치, 지우는 법), `THIRD_PARTY_NOTICES.md`(크레이트 라이선스 + yt-dlp/ffmpeg), `docs/RELEASE_CHECKLIST.md`(준비율 표).
6. 검증: 단위 테스트, 실제 네트워크 수동 테스트, UI 자동화로 실제 창 조작 스모크, Windows Defender 검사.
- 내가 못 하는 것(남는 5%): 코드 서명, 포털 서버 업로드, 다른 PC(깨끗한 Windows)에서의 실행 확인, 앱 자체 라이선스 결정.

## 계획검토 반영 (Codex sol, 2026-11-25, REVISE → 반영 후 재검토 없이 진행)
1. yt-dlp 업데이트는 요청한 항목과 별개의 Job 으로 돌린다(그 항목을 취소해도 다른 항목이 기다리는 업데이트는 끝난다). 실행 중인 다운로드를 멈추고 업데이트하지는 않는다 — yt-dlp 는 실행 중인 exe 를 이름을 바꿔 교체한다.
2. 임시 파일 이름에 프로세스 번호를 넣어(`.{pid}.part`, `ffmpeg.{pid}.zip`) 창 두 개가 같은 파일에 쓰지 않는다.
3. 변환 출력 경로는 고르는 즉시 빈 파일을 만들어 선점한다(동시에 `photo.png`·`photo.webp` → `photo.jpg` 충돌 방지). 같은 작업이 이미 대기·실행 중이면 다시 넣지 않는다.
4. 다시 시도는 새 id 를 받는다(취소된 실행의 늦은 메시지가 새 실행에 섞이지 않는다). 실행 중 항목은 작업자가 끝났다고 알릴 때까지 자리를 차지하고, 지울 수 없다.
5. GPU 실패 후 CPU 재시도는 그 항목 안에서 바로 한다(드문 경우 CPU 인코딩이 2개까지 겹칠 수 있음 — 받아들임). 취소는 재시도하지 않는다.
6~7. 1080p 초과 선택식에 오디오를 붙였다. M4A 는 m4a 스트림을 먼저 고르고, 없을 때만 변환한다.
8. 자막은 `--write-subs --write-auto-subs --embed-subs --compat-options no-keep-subs` (올린 자막 + 자동 자막, 넣은 뒤 .vtt 삭제).
9. PNG/WebP 에는 `format=rgb24` 를 쓰지 않는다(투명 유지). 인코더별 화질 인자를 따로 둔다.
10. 플레이리스트는 끝난 파일마다 기록에 한 줄씩 남긴다.
11~12. 배포 스크립트는 명령마다 종료 코드를 확인하고, 낡은 exe 를 먼저 지우고, 서명 뒤에 해시를 낸다. `--target x86_64-pc-windows-msvc` 를 명시한다.
13. 새 버전 주소는 `https://xtool.duckdns.org/` 로 시작할 때만 받는다. 앱은 파일을 받지 않고 브라우저만 연다.

## 코드 리뷰 (/code-review high, 2026-11-25) — 중요 4, 사소 6, 전부 수정
- GIF `-t 30` 을 `-i` 앞으로(뒤에 두면 영상 전체를 읽음). 진행률도 30초 기준.
- yt-dlp 업데이트는 실행당 한 번만 시도(성공·실패 무관). 실패는 "오늘 했음"으로 적지 않아 다음 실행에서 다시 한다.
- "도구 다시 받기"는 준비 중이면 기다리지 않고 실패로 알린다(`try_lock`), 시작 준비가 끝날 때까지 비활성, 두 파일 모두 지움.
- 폴더·파일 열기는 별도 스레드에서(응답 없는 네트워크 드라이브가 창을 멈추지 않게). 빈 경로는 열지 않는다(바탕 화면 루트가 열리던 것).
- 오류 문장 앞 구절 유지, 자막·썸네일 파일은 작업 제목을 바꾸지 않음, 제목줄 버전 글자는 선택 불가, 패닉 로그 테스트 정리.
